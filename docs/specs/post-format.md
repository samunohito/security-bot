# 投稿本文とハッシュタグ

広いセキュリティ動向を流し読みし、関心のある分野・技術テーマ・メーカー・製品の投稿を探すための仕様。
利用製品の事前登録は要求しない。

個別・まとめの選択と掲載条件は[発信方法と掲載理由](publishing-policy.md)に従う。
まとめ投稿は検証済みの個別項目を箇条書きで並べ、期間・分割番号と共通の `#NVD` を付ける。
個別項目の製品タグはまとめ全体へ付けない。

## 投稿の構成

```text
[High] CVE-2026-97860
ヤマハ YMS-VPN8／YMS-VPN8-CP
Windowsサービスのファイルパスの引用符不備

影響: システムドライブへの書き込み権限を持つユーザーにより、SYSTEM権限で任意のコードが実行される可能性があります。

出典: https://jvn.jp/jp/JVN30675482/

#ネットワーク #パス処理 #ヤマハ #YMS_VPN8 #YMS_VPN8_CP
```

- CVEがある場合のみ、深刻度とCVEを先頭行に置く。記事内の別CVEの深刻度を転用しない。
- 対象名と問題の見出しは各1行とし、概要の重複を避ける。
- 見出し・影響・対策・未確認事項・出典・タグの間は空行で区切る。該当しない段落は省く。
- CVEがない場合は内部の情報源キーや深刻度を表示せず、対象名から始める。
  影響の段落がある場合も「影響:」を付けず、説明文として表示する。
- 更新・訂正は、先頭にそれぞれ `[更新]`・`[訂正]` を付ける。既存投稿への参照も維持する。
- 影響の成立条件、必要な権限、重要なバージョン境界を短縮のために省かない。
- CVEの影響が未確認の場合は「影響: 未確認」とし、判断に関係する未確認事項も維持する。

## 対策の表示

対策の収集・引用照合・意味検証は通常の更新指示にも行う。
投稿には、次の例外情報が出典で確認でき、対策本文に含まれる場合だけ表示する。

| 種別               | 表示する情報                               |
| ------------------ | ------------------------------------------ |
| `unpatched`        | 修正版が未提供であること                   |
| `workaround`       | 機能の無効化など、具体的に実行できる回避策 |
| `additional_steps` | 鍵の交換など、更新以外にも必要な作業       |
| `patch_warning`    | 一部バージョンが未修正など、修正版の注意点 |

通常の更新指示は `routine_update` とし、投稿では省く。
「アップデート、またはワークアラウンドを実施」のように回避策の内容がない定型文もこれに含める。
修正版の有無が未確認であることを「未提供」と断定しない。
通常更新と例外が併記される場合は例外を優先し、その内容を本文に含める。

表示の省略を理由に品質ゲートを緩めない。厳格な品質ゲートでは従来どおり概要・影響・対策が揃い、
未確認事項がないことを要求する。

## タグの分類と選定

LLMはタグ候補と引用を返す。プログラムが構造・分類・名称を検査した後、投稿時のタグ表記で重複を除き、
分類ごとに候補の先頭から上限内で採用する。重複は枠を消費しない。
採用したタグと本文を引用照合し、既存の別推論による意味検証にも渡す。個数超過だけで投稿全体を保留しない。
用途は最大1個、テーマは最大2個、メーカーは最大1個、製品は最大2個、合計最大6個とする。
該当する候補がなければ選ばず、「その他」で埋めない。

この整理は新規要約、管理APIによる再生成、文字数超過時の短縮生成に適用する。
既存の保存済み不合格要約・保留配信は自動で変更・再送しない。

### 用途

動作環境より対象製品の主な用途を優先する。

| タグ            | 選定基準                                                  |
| --------------- | --------------------------------------------------------- |
| `#ネットワーク` | VPN、ルーター、DNS、プロキシなど                          |
| `#OS`           | OS本体、カーネル、ドライバー。OS上の一般アプリは含めない  |
| `#ブラウザ`     | ブラウザ本体と拡張機能                                    |
| `#業務アプリ`   | グループウェア、文書管理、業務システム                    |
| `#Web基盤`      | Webサーバー、CMS、Webフレームワーク                       |
| `#開発ツール`   | IDE、ビルドツール、パッケージ管理                         |
| `#クラウド基盤` | 仮想化、コンテナ、クラウド管理                            |
| `#データベース` | DB本体と管理ツール                                        |
| `#組み込み機器` | IoT、家電、産業機器。主用途がネットワークならそちらを優先 |

### 技術テーマ

問題の原因や成立条件に直接関係する場合だけ選ぶ。

| タグ                | 選定基準                                           |
| ------------------- | -------------------------------------------------- |
| `#認証`             | 本人確認、ログイン、セッション管理の問題           |
| `#アクセス制御`     | 権限チェックの不備、本来許されない資源へのアクセス |
| `#暗号`             | 暗号方式、鍵、証明書検証そのものの問題             |
| `#メモリ安全性`     | バッファオーバーフロー、解放後使用など             |
| `#インジェクション` | SQL、コマンド、スクリプトなどの不正な解釈・実行    |
| `#パス処理`         | パストラバーサル、ファイルパスの解釈の問題         |
| `#サプライチェーン` | 配布物、依存関係、更新経路の侵害                   |

VPNが暗号を使うという理由で暗号タグを付けたり、任意コード実行という被害だけから
インジェクションと判断したりしない。依存ライブラリの通常の脆弱性だけではサプライチェーンとしない。

### メーカー・製品

出典の引用に現れる対象名を抽出し、企業名の翻訳・別名・略称を推測しない。
多数の製品を含む場合は、出典に明示された製品群の名前を優先する。
名前が似ているだけで別製品を同一の製品群としてまとめない。

抽出名称はUnicode NFKCで正規化し、英字を大文字へ、記号や空白の並びを `_` へ変換する。
ただし `+` は `_PLUS`、`#` は `_SHARP` とし、`C++` と `C#` を区別する。
例：`YMS-VPN8` は `#YMS_VPN8`、`Acme Server` は `#ACME_SERVER`。
固定分類の表記は変えない。用途・テーマ・メーカー・製品の順で末尾に並べ、重複は除く。
メンションやMFMを含む不正な名称、数字だけのタグは出力しない。

## 根拠・保存形式との互換性

対象名と各タグは概要などと同じ形式の引用を持つ。引用の実在、数値、複数CVEの記事での対象帰属を検証する。
メーカー・製品名は引用内に存在することも検証する。分類の意味、対象との関係、対策種別、
影響条件の保持は既存の意味検証で確認する。

追加フィールドのない保存済み要約も読み込めるようにする。
旧要約は自動で再生成せず、対象名は元の見出しで代替し、タグと種別不明の対策欄は省く。
新しい対象名・分類は新規に生成する要約から反映する。
新規生成・再生成・短縮の結果では、対策本文があるのに対策種別が欠けた要約は保留する。
この本文仕様自体は、改訂・配信・予算の状態遷移を定めない。

## Misskeyへの送信

本文中の任意タグ・メンション・MFMはエスケープし、検証済みの末尾タグだけをタグとして出す。
タグ抽出は有効にするが、メンションと絵文字の自動抽出は無効のままとする。
文字数制限は参照URLを含む投稿全体に適用し、短縮時にも同じ根拠・品質検証を行う。

Misskeyの抽出制御は2026-10-28に[公式のnotes/create実装](https://github.com/misskey-dev/misskey/blob/develop/packages/backend/src/server/api/endpoints/notes/create.ts)で確認。
Workers
AIへの構造化出力指定は既存の[JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/)を継続利用する（同日確認）。
