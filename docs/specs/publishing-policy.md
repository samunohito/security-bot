# 個別投稿とNVD Highのまとめ投稿

対象は発信方法の選択、掲載理由、まとめの期間、掲載履歴。本文の根拠・品質・文字数の規則は[投稿本文](post-format.md)に従う。

## 発信方法と緊急度

`publishing.mode` は `individual`（省略時の従来方式）または `nvd-high-digest`。
後者では次のように分ける。情報源は設定のIDでなくkindで識別する。

| 現在の根拠                            | 発信方法 | 緊急度               |
| ------------------------------------- | -------- | -------------------- |
| KEV・個別CVEの悪用確認                | 個別     | 緊急                 |
| JVN・JPCERT等の非NVD根拠              | 個別     | 既存の緊急判定に従う |
| NVDのみ・Critical（最大CVSS 9.0以上） | 個別     | 通常                 |
| NVDのみ・High（7.0以上9.0未満）       | まとめ   | 通常                 |

情報源で取得したスコアの最大値を使う従来の算出を維持する。
記事全体の悪用やスコアを複数のCVEそれぞれの確定情報にはしない。

## 新規公表・初評価・昇格

NVDのみの掲載理由は、新規公表、未評価から初めてHigh以上と評価された場合、Medium以下→High、High以下→Critical。
古い公表日のCVEでも観測後の昇格を対象とする。新規公表日はNVDのpublishedであり、CVE番号の年やlastModifiedではない。
初回に見る古い既評価CVEの状態から、過去の昇格を推測しない。

同じ重大度内のスコア変動、翻訳追加、通常の修正だけでは再掲載しない。
投稿先ごとに掲載した最大重大度を保持し、降格後の再昇格だけで同じ通知を繰り返さない。
High掲載後のCritical・悪用確認は個別投稿する。掲載済みCVEの却下訂正も対象。
非NVD根拠を得た場合は、従来の個別投稿と更新の判定に従う。

公表日・根拠の更新日時・掲載理由の検知日時を区別する。
NVDの新規・昇格・初めての悪用確認では検知日時を配信鮮度・運用上のcutoffの判定に使う。
NVDは古い更新も収集・観測してから判定し、他の情報源の既存cutoff判定は維持する。

## まとめ作成と配信

既定の `publishing.digestIntervalSeconds: 21600` では、日本時間の0・6・12・18時に直近の期間を閉じる。
既存Cronの最初の実行で作成し、空なら投稿しない。準備が遅れた項目は後続の期間へ持ち越す。
区切りは作成時刻であり、分割を含む全投稿の送信完了時刻ではない。

各項目はCVE、掲載理由、スコア、対象名、影響、出典を含む。根拠付き要約の検証を省かない。
例外対策と重要な成立条件も維持する。まとめ全体をLLMで自由生成しない。
スコアの高い順、検知の古い順、CVEキー順とし、期間・番号・出典込みで投稿先の `targets.maxCharacters` 内に分割する。
件数の固定上限は設けず、まとめ専用の本文形式は[投稿本文](post-format.md#nvd-highのまとめ項目)に従う。
単一項目が長すぎる場合は理由付き保留にし、文字列を切断して無理に投稿しない。

分割ごとに通常枠を1つ消費する。投稿間隔・上限・最低間隔・緊急優先を維持する。
まとめ待ちHighが個別対象になった場合、未送信のまとめを無効化し、残るHighを次回の集計で再構成する。
一部の項目だけが鮮度期限を超えたまとめは、有効な項目も失わないよう、閉じた集計期間を再開して再構成する。

## 掲載履歴と失敗

送信成功を記録した分割に含むCVEだけを掲載済みにする。準備済み・プレビュー・保留は成功扱いにしない。
送信開始時に、まとめの全所属の現在改訂・根拠・重大度・品質を原子的に確認する。
送信中と結果不明の本文・所属を差し替えない。
unknownを自動再送せず、その所属を別のまとめへも再投入しない。
送信結果待ちのため未解析だった新しい版は延期し、確実な未送信が判明した場合に解析を再開する。
現行版の要約が失われた場合は完了済み解析を再開し、検証が済むまで送信を待つ。
品質不合格の要約をこの回復処理で無条件に再生成しない。
解析ジョブを作成時と異なる設定で完了扱いにはせず、設定待ちとして保留する。
現在の設定用の解析を登録し、元の設定へ戻った際は設定待ちの解析も再開する。

Critical・悪用・却下訂正では、そのCVEを掲載したまとめへの参照も使える。
AI予算と品質ゲートは維持するため、投稿数の減少はAI呼出数や全件掲載を保証しない。
期限超過・品質不合格・長すぎる項目は管理機能から確認する。
要約前に期限切れとなった場合も、解析ジョブを理由付きで保留する。再試行も現在の条件を再検証する。

## 既存DBへの導入

migration適用後、初回の新方式実行で現在の重大度を観測の初期値にし、既存の掲載履歴を引き継ぐ。
既存のHigh滞留を一括で新規公表や昇格とみなさない。
保存済み要約と未送信個別配信も送信前に再判定する。sending・unknownは自動で変更しない。
掲載履歴と観測の基準は、古いジョブや根拠の整理で削除しない。
一度まとめ方式を導入した後は、個別方式へ切り替えた間も観測を続け、再開後の昇格を失わない。
方式の切替を理由に保留した未送信まとめは、方式再開後に版・品質・鮮度を再検証して送信を再開する。
非NVDのCVE関連が復旧した場合も、現在の根拠から個別対象へ戻った未送信配信を復帰させる。
方式の切替だけでは掲載済みの同じ版を再送しない。未送信の個別Highはまとめ方式へ再判定し、準備済み・保留の個別配信でまとめ候補を塞がない。
